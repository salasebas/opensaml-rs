# 0.6 to 0.7

This guide shows you how to upgrade `saml-rs`, `opensaml`, `samlify`, or
`samlet` from the latest `0.6.x` release to `0.7.x`.

If the code calls `strict()`, replace that call first. If `Default`, `new`,
`try_new`, or a config builder was enough, go to
[Point constructors at the preset you need](#point-constructors-at-the-preset-you-need).

## Replace `strict()`

This breaks code that calls `SpValidationPolicy::strict`,
`IdpValidationPolicy::strict`, or `LogoutPolicy::strict`.

Who must change: that code.

If the call needs no extra check, use Recommended:

```rust
let policy = SpValidationPolicy::recommended();
```

If the service provider must still require a signature directly on the
Assertion:

```rust
let require_assertion_signature = SpValidationPolicy {
    assertions: AssertionSignaturePolicy::RequireSigned,
    ..SpValidationPolicy::recommended()
};
```

If it must still require the RSA-SHA2 XML-DSig profile, and Assertion
signatures can stay optional:

```rust
let require_rsa_sha2 = SpValidationPolicy {
    xml_signatures: XmlSignatureProfile::StrictRsaSha2,
    ..SpValidationPolicy::recommended()
};
```

If it must do both, set both fields. The two checks are independent. Why they
stay separate is in
[Validation presets](../../explanation/validation-presets.md).

If the service provider must still sign `AuthnRequest`s and reject a bearer
assertion that omits `<AudienceRestriction>`:

```rust
let sp = SpValidationPolicy {
    assertions: AssertionSignaturePolicy::RequireSigned,
    authn_requests: AuthnRequestSigningPolicy::Sign,
    audience: AudienceValidationPolicy::Validate,
    ..SpValidationPolicy::recommended()
};
```

If the identity provider must still reject an unsigned `AuthnRequest`:

```rust
let idp = IdpValidationPolicy {
    authn_requests: AuthnRequestValidationPolicy::RequireSigned,
    ..IdpValidationPolicy::recommended()
};
```

Replace `LogoutPolicy::strict()` with `LogoutPolicy::recommended()`. Both
require a signature on logout requests and responses.

## Point constructors at the preset you need

This breaks code that depended on `Default`, `new`, or `try_new` staying on
Compatibility, and code that depended on a config builder staying on the
removed bundle.

Who must change: that code.

`SpValidationPolicy::default`, `IdpValidationPolicy::default`,
`LogoutPolicy::default`, and `SpConfig` and `IdpConfig` `new`, `try_new`, and
`builder` are Recommended.

An identity provider on the builder default accepts an unsigned
`AuthnRequest` and can issue an assertion for it. A service provider on the
builder default accepts a bearer assertion that omits `<AudienceRestriction>`.
`AuthnRequest` signing and a direct Assertion signature are off as well.

If the service provider must keep those checks:

```rust
let sp = SpValidationPolicy {
    assertions: AssertionSignaturePolicy::RequireSigned,
    authn_requests: AuthnRequestSigningPolicy::Sign,
    audience: AudienceValidationPolicy::Validate,
    ..SpValidationPolicy::recommended()
};
```

If the identity provider must keep the unsigned-request rejection:

```rust
let idp = IdpValidationPolicy {
    authn_requests: AuthnRequestValidationPolicy::RequireSigned,
    ..IdpValidationPolicy::recommended()
};
```

To keep the legacy permissive preset on a builder:

```rust
let sp = SpConfig::builder(entity_id)
    .acs_endpoint(acs)
    .validation(SpValidationPolicy::compatibility())
    .build()?;
```

If `try_new` or `builder().build()` returns `SamlError::Unsupported`, the
build has no crypto provider. Recommended requires one: logout messages must
be signed, and a CBC-encrypted assertion requires a Response signature. Select
`compatibility()`, or another policy that does not require signatures, to
keep that build. `new` does not validate.

## Leave field defaults and raw settings

Leave `ResponseSignaturePolicy::default` and
`AuthnRequestValidationPolicy::default` as they are. They are not the
Recommended preset. Raw settings defaults are unchanged.
`SpValidationPolicy::compatibility`, `IdpValidationPolicy::compatibility`,
and `LogoutPolicy::compatibility` stay available by name.
